## 2. アーキテクチャ

```
┌─ ブラウザ (SPA / 素のJS・ビルド不要) ─────────────────┐
│ index.html + css/style.css                             │
│ js/api.js     … fetchラッパ・全APIクライアント          │
│ js/app.js     … 状態(State)・権限判定・ルーティング・モーダル │
│ js/views.js   … 各ビューの描画（ボード/表/ガント/ホーム/…）│
│ js/detail.js  … タスク詳細ドロワー                      │
│ js/charts.js  … 依存ゼロのSVGチャート（donut/hbar/line）│
└──────────── fetch (Cookieセッション) ────────────┘
                     │
┌─ app.py (FastAPI 単一ファイル) ────────────────────┐
│ セッションMW → resolve_uid()（偽装制御） → 権限チェック   │
│ REST API（/docs にOpenAPI） ＋ エクスポート生成          │
│ 起動時: SCHEMA 適用 → migrate()（自動マイグレーション）    │
└──────────────── sqlite3 ───────────────────┘
                     │
        data/pjboard.db（SQLite 1ファイル）

別プロセス: mcp_server.py（MCP stdio → REST 経由で操作。AIクライアント用）
```

### DBスキーマ（テーブルと役割）

| テーブル | 役割 |
|---|---|
| orgs | 組織（名前・カラー） |
| members | ユーザー。org_id（所属）/ account_type（internal・external）/ org_role（組織権限）/ password_hash |
| sessions | ログインセッション（token → member_id） |
| projects | プロジェクト。custom_fields（JSON）/ settings（JSON・既定値とマージ） |
| project_members | PJへのアサイン＝PJロール（leader/member/advisor/external）＋外部用閲覧フラグ |
| statuses | ボード列（PJごと。is_done=完了扱い） |
| tasks | タスク。parent_id（WBS階層）/ deps（先行タスク）/ tags / custom_values / milestone |
| comments | コメント（イシュー・議論・タスク詳細で共通の単一ソース） |
| task_links | 関連リンク（Wiki/Figma/リポジトリ等） |
| project_notes | 共有ノート（カテゴリ・ピン留め・テンプレート由来） |
| activities | 変更履歴（作成・状態・担当・進捗・コメント・メンバー増減） |

- **マイグレーション方針**: 起動時の `migrate()` が PRAGMA で列を確認し、無ければ `ALTER TABLE` で追加。
  破壊的変更なし・旧DBそのまま起動可。（例: 権限導入時は既存メンバーを leader に引き上げて従来挙動を維持）

## 3. 権限モデル（2層）

**実効権限 = 組織権限 × PJロール**。`effective_role()`（app.py）が唯一の判定箇所。

### 組織権限（members.org_role）

| 値 | ランク | できること |
|---|---|---|
| manager（マネージャー） | 4 | **全PJの暗黙管理者**（アサイン不要・メンバー欄に非表示）＋ユーザー/組織管理＋左下「表示のみ切替」 |
| site_admin（サイト管理者） | 3 | ユーザー追加・組織管理・パスワードリセット・各種設定。**PJの暗黙管理者ではない** |
| professional（プロ職） | 2 | 全PJの暗黙管理者（マネージャー同等のPJ権限。ユーザー管理は不可） |
| staff（一般） | 1 | PJロールに従う |

### PJロール（project_members.role）

| 値 | 実効権限 | できること |
|---|---|---|
| leader | admin | そのPJの全操作（設定・メンバー・スケジュール） |
| member | member | **自分の担当タスク**の状態/進捗/実績/説明/タグ/タイトルのみ。日程はPJ設定で緩和可。未割当タスクのセルフアサイン可 |
| advisor（ご意見番） | advisor | 閲覧＋コメント |
| external（外部） | external | 下記 |
| （未アサインの社内） | viewer | **全PJ閲覧＋コメント可**（←PJ外の人に@メンションで意見を求められる設計の肝。PJ設定でOFF可） |

### 外部ユーザー（account_type=external）

- 社内ロールと**入替不可**（サーバーが400で拒否）
- **参加PJしか見えない**（bootstrap 段階で絞り込み）
- PJごとに「コメント閲覧」「タスク詳細閲覧」を制限可。**変更できるのはそのPJのメンバー管理（PJ管理者）のみ**
- 制限中はコメント件数=0表示・コメント系アクティビティ除去・詳細APIは403

### 強制の仕組み

- UI: 権限がない操作はボタン非表示・入力 disabled
- サーバー: `resolve_uid()` がセッションユーザーと突き合わせ（他人としての操作・閲覧を403）、
  各エンドポイントで `effective_role` を検査して403
- **緩め運用**: 未ログイン（Cookieなし）のAPI直叩き＝スクリプト・MCP は権限チェックなしで通す

### デバッグ機能（2系統・別管理）

| | 右上 🔧 ログイン完全切替 | 左下 👁 表示のみ切替 |
|---|---|---|
| 表示条件 | **全ログインユーザー**（開発時専用） | マネージャーのみ |
| 動作 | `/api/auth/debug-login` でセッションごと張替え。以後完全にそのユーザー | ログイン維持のまま view用の user_id だけ変更。バッジ表示＋ワンクリック解除 |
| 本番 | **PJBOARD_DEBUG=0 で無効化（削除想定）** | 残す運用想定 |

※ 左下で表示切替中は、左ペインに「プロジェクト」「プロジェクトメンバー」のみ残し、ホーム・組織管理ナビは非表示になる（footerの切替UIとバッジは残る）。

## 5. API・AI連携

- 全操作が REST（`/docs` = Swagger UI）。書き込みは `actor_id` でユーザー権限が適用される
- AI向け: `GET /api/ai/help`（エージェント向けガイド）／`GET /api/ai/context[?project_id=]`（LLM向け要約JSON）
- **MCPサーバー** `mcp_server.py`: 依存ゼロのstdio実装。10ツール（list_projects / get_project / create_task / update_task / get_task / add_comment / list_discussions / get_notes / update_note / user_overview）。
  環境変数 `PJBOARD_URL`・`PJBOARD_ACTOR_ID`（操作ユーザー）。登録例は README 参照

## 7. 開発メモ（ハマりどころ）

- **静的ファイルのブラウザキャッシュ**: Cache-Control 無指定だと更新JSが配信されない事故が起きた。
  現在は JS/CSS/HTML に `no-cache`（ETag再検証・304運用）を付与済み。デプロイ後は再読込だけで最新化される
- **uvicorn はホットリロードなし**で起動している。app.py 変更後はプロセス再起動が必要（開発時は `--reload` を付けても良い）
- **日本語フォルダ名**: uvicorn/SQLite とも問題なし。Git 管理する場合もパスに注意すれば可
- PowerShell から `python mcp_server.py` にパイプするとBOMが混入することがある（lstripで対処済み。実際のMCPクライアントでは発生しない）
