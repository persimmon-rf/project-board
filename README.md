# PJ Board — 社内向けセルフホスト・プロジェクト管理ツール

社内 AWS 環境にデプロイして使う、軽量なプロジェクト管理ツール。
外部 CDN・外部 API に一切依存しないため、閉域ネットワークでも動作します。

## 機能一覧

| カテゴリ | 内容 |
|---|---|
| ログイン | 各ユーザーが**自分のアカウントでログイン**して使用（Cookieセッション・パスワードはsalt付きSHA-256）。初期はパスワード未設定で空欄ログイン→🔑で各自設定。サイト管理者以上はリセット可 |
| 組織・ユーザー | ユーザーは**組織**に所属。「組織・ユーザー管理」ページ（**サイト管理者以上のみ**）で組織・ユーザー・アカウント種別（社内/**外部**）・**組織権限**を管理 |
| 権限（2層モデル） | **組織権限**（マネージャー＞**サイト管理者**＞プロ職＞一般）×**PJロール**（リーダー/メンバー/ご意見番=Advisor/外部）の掛け合わせで実効権限が決まる。**マネージャー・プロ職は全PJの暗黙管理者**（アサイン表示不要）。**社内の全ユーザーは全PJを閲覧でき、未アサインでもコメント可**→PJ外の人にメンションして意見を求められる（PJ設定でOFF可）。**サイト管理者**はユーザー追加・組織管理・パスワードリセットが可能だがPJの暗黙管理者ではない。メンバー=自分の担当タスクの状態・進捗等のみ（日程はPJ設定で緩和可）。サーバー側でも403で強制、actor_id なしのAPI直叩きは素通し（緩め運用） |
| 外部ユーザー | 社外・組織外の別枠アカウント。**社内ロールとの入替は不可**（サーバーが400で拒否）。**参加プロジェクトしか見えず**、「コメント閲覧」「タスク詳細閲覧」の制御は**そのPJのメンバー管理（PJ管理者）からのみ**変更可（WBS・ガント・進捗は見える） |
| デバッグ切替（2種類） | **右上「🔧」＝ログイン完全切替**（開発時専用・**どのユーザーでも表示**。セッションごと入れ替わり、以後は完全にそのユーザー。本番は環境変数 `PJBOARD_DEBUG=0` で無効化＝削除想定）。**左下「👁 表示のみ切替」＝マネージャー専用**（ログインは維持したまま見え方だけ切替。切替中もボックスは残り、オレンジバッジ＋ワンクリック解除。本番でも残す想定） |
| コメント一覧・議論ページ | 💬タブでコメントスレッドを一覧化し、クリックで**チャット風の議論専用ページ**へ（GitHub Issue風。上部にタスク概要、下部に入力欄、@メンション挿入つき）。**元データはタスク詳細のコメントと同一** |
| ノート | 📖タブでPJのルール・メモを共有。**テンプレート**（環境/社内体制/先方窓口/定例/開発ルール/ツール/決定事項ログ/障害連絡フロー）が新規PJで自動作成され、後から埋める運用。テンプレはPJ設定で編集可 |
| プロジェクト設定ページ | ⚙からリーダー・組織上位者のみ。基本情報／ボード列／カスタムフィールド／**表示設定**（見積・優先度・タグ等を非表示化）／**権限の細部**（メンバーの日程変更許可など）／**外部ユーザー既定**／ノートテンプレート／アーカイブ・削除 |
| マイダッシュボード | プロジェクトに紐づかない**横断ビュー**（🏠）。自分が関与する全プロジェクトの進捗カード・自分の未完了タスク（期限順）・期限超過・横断アクティビティを一望。操作ユーザーを切り替えると本人視点に変わる |
| カンバンボード | ステータス別 / **担当者別** の2モード。ドラッグ&ドロップでステータス変更・**メンバーへの割り振り** |
| テーブルビュー | 同じデータを表形式で。列ヘッダーでソート、セル内で**インライン編集**（ステータス・担当・優先度・日付・見積） |
| WBS / ガント | 親子タスクで WBS 番号を自動採番。**編集モード**（管理者のみ）で: バー中央＝日程移動／**左端＝開始日のみ**・右端＝期限のみ変更／空きレーンをドラッグ＝その期間で新規タスク作成／**行を⠿でドラッグ＝並べ替え**／⭢⭠＝**階層変更（インデント）**／＋＝**サブタスク追加**。日幅ズーム・タスク名列の幅調整・依存線・マイルストーン・今日ライン・週末シェード |
| タスク詳細 | スライドオーバーパネルで一覧⇔詳細を高速に往復。**イシュー風のコメントスレッド**で議論、変更履歴も自動記録 |
| 情報の紐づけ | サブタスク・先行タスク・タグ・関連リンク（Wiki/Figma/リポジトリ等）・カスタムフィールドをタスクに紐づけて一覧管理 |
| ダッシュボード | 統計カード・ステータス円グラフ・担当者別残タスク・優先度分布・週別負荷チャート・期限間近リスト・簡易ボード・アクティビティ |
| エクスポート | **HTML（案件終了後のアーカイブ用・完全スタンドアロン）** / **Excel (.xlsx 4シート)** / CSV（BOM付きUTF-8） / JSON（バックアップ・外部連携用） |
| 共有リンク | URLハッシュでビュー・タスク詳細まで共有可能（例: `#/p/1/board/t/12`）。ブラウザ再読込でも同じ画面を復元 |
| 拡張性 | プロジェクトごとの**カスタムフィールド**（テキスト/数値/日付/選択肢）、ボード列の追加・編集、REST API（`/docs` に OpenAPI ドキュメント自動生成） |
| フィルター | キーワード・担当者・優先度・タグ・完了非表示。全ビュー共通で効く |

キーボード: `n`=タスク追加, `1`〜`4`=ビュー切替, `Esc`=閉じる, `Ctrl+Enter`=コメント送信

## ローカル起動

```powershell
pip install -r requirements.txt
python -m uvicorn app:app --host 0.0.0.0 --port 8100
```

→ http://localhost:8100 を開く。初回起動時にデモデータ入りの SQLite DB（`data/pjboard.db`）が生成されます。

## AWS へのデプロイ

### 構成A: EC2（最も簡単）
```bash
docker build -t pjboard .
docker run -d --name pjboard -p 8100:8100 -v /opt/pjboard/data:/app/data --restart unless-stopped pjboard
```
- ALB or セキュリティグループで社内 IP レンジのみ許可
- データは `/opt/pjboard/data/pjboard.db` の1ファイル。バックアップはこのファイルをコピーするだけ

### 構成B: ECS Fargate
- 上記イメージを ECR に push → Fargate サービス化
- **EFS を `/app/data` にマウント**（SQLite の永続化に必須）
- タスク数は 1 に固定（SQLite のため。複数台にする場合は RDS 化が必要 → 下記）

### 認証について（本番運用時の推奨）
アプリ自体に認証はありません（たたき台のため）。社内公開時は以下のいずれかを前置してください:
- ALB + **Cognito 認証**（社内 IdP / Google Workspace 連携）— コード変更不要でおすすめ
- ALB + OIDC（既存の社内 SSO）
- もしくは VPN / 社内 IP 制限のみで運用

## データ構成・拡張ポイント

- DB は SQLite 1ファイル（`PJBOARD_DB` 環境変数でパス変更可）
- スキーマは `app.py` 冒頭の `SCHEMA` 定数。テーブル: orgs / members(=ユーザー、org_id で組織所属・account_type で社内/外部) / project_members(アサイン＝role・閲覧フラグ) / project_notes / projects / statuses / tasks / comments / task_links / activities
- 旧スキーマのDBは起動時に自動マイグレーション（`migrate()`）: 既定の組織を作成して全ユーザーを所属させ、従来挙動を保つため既存プロジェクトに全ユーザーをアサイン
- REST API は http://localhost:8100/docs で全エンドポイント確認可能（Swagger UI）。外部ツール連携やスクリプトからの一括投入もこの API 経由で可能
- フロントは `static/` 配下の素の HTML/CSS/JS（ビルド不要）。ビューの追加は `static/js/views.js` に関数を足し、`app.js` の `render()` に分岐を追加するだけ
- 複数人同時利用は「最後の保存が勝つ」楽観方式。大規模化する場合は SQLAlchemy + PostgreSQL(RDS) への差し替えを想定した構成（DB アクセスは `app.py` に集約済み）

## AI連携（MCP / API）

- **MCPサーバー**: `mcp_server.py`（標準ライブラリのみ・依存なし）。Claude Code 等に登録すると list_projects / get_project / create_task / update_task / add_comment / get_notes などがツールとして使える:

```json
{
  "mcpServers": {
    "pjboard": {
      "command": "python",
      "args": ["D:/claude/会社/プロジェクト管理/mcp_server.py"],
      "env": { "PJBOARD_URL": "http://localhost:8100", "PJBOARD_ACTOR_ID": "1" }
    }
  }
}
```

- **AI向けエンドポイント**: `GET /api/ai/help`（使い方ガイド・Markdown）／`GET /api/ai/context`（全PJ要約）／`GET /api/ai/context?project_id=N`（1PJの全データ: WBS・ノート・コメント）
- OpenAPI (`/docs`, `/openapi.json`) の説明文もAIが読める前提で記述。書き込み時は `actor_id` を渡すとそのユーザーの権限で動作

## 既知の制限（たたき台）

- アプリ内ログインは簡易実装（Cookieセッション＋SHA-256）。インターネット公開時はALB+Cognito等の前置とHTTPS化を必須とすること
- 未ログインのAPI直叩き（スクリプト・MCP）は権限チェックなしで通る緩め運用。締めたい場合は resolve_uid() の未ログイン分岐を401に変えるだけ
- ファイル添付は未対応（関連リンクで代替。S3連携が次の拡張候補）
- リアルタイム同期なし（他ユーザーの変更は再読込で反映）
- 通知（メール / Slack / Teams）未対応
